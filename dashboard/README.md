# Диспетчерская панель (React)

Клиентская часть платформы. Заменила Streamlit-приложение: старые
`dashboard/app.py` и `dashboard/requirements.txt` удалены, вместе с ними ушла
реализация карт на folium / OpenStreetMap.

## Провайдер карт

Основной провайдер — **2ГИС Карты** (MapGL JS API), официальный пакет
`@2gis/mapgl`. Yandex и Google остаются доступными как коммерческие запасные
варианты. OpenStreetMap намеренно не поддерживается и не подключается: его тайлы
требуют либо собственного tile-сервера, либо ключа стороннего оператора, а
условия использования исключают бесплатное подключение к продакшену.

| Переменная | Провайдер | Роль |
|---|---|---|
| `VITE_TWOGIS_API_KEY` | 2ГИС Карты (`@2gis/mapgl`) | основной, выбирается первым |
| `VITE_YANDEX_API_KEY` | Яндекс Карты (`@pbe/react-yandex-maps`) | запасной |
| `VITE_GOOGLE_MAPS_API_KEY` | Google Maps (`@react-google-maps/api`) | запасной |

`VITE_MAP_PROVIDER` (`2gis` по умолчанию) задаёт предпочтение явно: `2gis`,
`yandex` или `google`. При `auto` выбирается первый готовый из порядка
2ГИС → Яндекс → Google. Если не задан ни один ключ, вместо карты выводится
поясняющее состояние — молчаливый откат на OSM невозможен по построению.

Провайдеры подгружаются через `React.lazy`, поэтому неиспользуемый SDK (291 КБ
для Google) не попадает в бандл активного провайдера.

### Особенности 2ГИС: порядок координат

2ГИС использует порядок **GeoJSON — `[longitude, latitude]`**, тогда как Яндекс и
Google ждут `[latitude, longitude]`, а бэкенд отдаёт именно `[lat, lon]`.
Поэтому в `src/lib/geometry.js` есть `toLngLat()`, и все координаты перед
передачей в 2ГИС разворачиваются. Если этот вызов забыть, вся отрисовка молча
уедет в океан — ошибки не будет, будет пустая карта.

Отрисовка: `HtmlMarker` для транспорта и остановок (можно обновлять на месте
через `setCoordinates`/`setContent`), `Polyline` для маршрутов и градиентных
сегментов каскада. Имперические объекты 2ГИС пересоздаются при изменении данных
и уничтожаются в cleanup-функции эффекта.

## Запуск

```bash
cp .env.example .env      # задайте ключ карт
npm install
npm run dev               # Vite на :5173, /api проксируется на :8000
```

Прод-сборка отдаётся nginx-образом, который же проксирует `/api` на `backend`:

```bash
VITE_YANDEX_API_KEY=... docker compose up --build dashboard
# http://localhost:8080
```

## Состояние

- **Серверное** — React Query. `placeholderData: keepPreviousData` держит
  предыдущий кадр, поэтому между опросами интерфейс не мигает и не блокируется.
  `refetchIntervalInBackground: false` — в фоновой вкладке опросы прекращаются.
- **Транспорт** — `useStreamTransport`: при заданном `VITE_WS_URL` поднимается
  WebSocket с экспоненциальным реконнектом, при обрыве polling возобновляется
  автоматически; при пустом `VITE_WS_URL` работает только polling. Бэкенд
  WebSocket-эндпоинта пока не отдаёт, поэтому режим WS включается только после
  его добавления на стороне FastAPI — код к этому готов.
- **Клиентское** — Context (`AppStateContext`) для источника данных, скорости,
  выбранного ТС и команды фокуса камеры. Команда фокуса несёт монотонный
  `token`, чтобы повторный запрос на ту же точку снова сработал.

## Цветовая шкала

| Задержка | Цвет | Смысл |
|---|---|---|
| 0 c | `#22c55e` | в графике |
| 120 c | `#eab308` | граница «красной зоны», совпадает с `risk` в бэкенде |
| 300 c+ | `#ef4444` | критическое опоздание |

Между опорными точками — линейная интерполяция по каналу RGB. Градиент
ΔETA рисуется посегментно: сплошной градиент по одному Polyline недостижим в
обоих SDK, поэтому каждый перегон окрашен своим цветом по `max(delay_from,
delay_to)`.
