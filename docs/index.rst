Границы сервисов
================

Система состоит из трёх сервисов с одной зависимостью:
``dashboard → backend → ML service``. Граница проходит по inference.

**ML service** (``ml-service/service.py``, ``src.predictor``, ``src.patterns``) -
единственный владелец модели: построение признаков, загрузка ``ml/model.cbm``,
forward pass CatBoost, калибровка вероятности и детекторы паттернов. Обслуживает
``GET /health``, ``GET /models`` и ``POST /predict`` (только батч: стоимость
признаков почти не зависит от числа строк).

**Backend** (``backend.main``, ``src.runtime``, ``src.ml_client``,
``src.ndtp*``, ``src.cascade``, ``src.batching``, ``src.deviation``) - приём
NDTP, выбор целевой остановки в горизонте 10-15 минут, оценка отклонения ТС от
расписания, каскад по сети, микробатчинг, API и метрики. Он **не импортирует**
``src.predictor`` и **не устанавливает** CatBoost: модель доступна только через
HTTP. Единственное, что он знает о ней, - адрес ``ML_SERVICE_URL``.

Граница проверяема: образ backend собран без ``catboost``, и
``ml/test_ml_integration.py`` поднимает настоящий ML service, прогоняет через
него батч-эквивалентность и причинность, а затем все режимы отказа -
недоступность, таймаут, некорректный ответ, потерю сервиса и восстановление.

**Общий модуль** ``src.schedule_index`` - единственное, что читают оба
сервиса: разбор ``schedule_plan.csv`` и геометрия остановок. Это библиотека в
монорепозитории, а не связь на уровне сервисов: ни CatBoost, ни inference.

Общий модуль расписания
========================

**Расписание** (``src.schedule_index``) - статическое представление плана: разбор
WKT с мемоизацией, сортировка по ``(tr_id, time_begin, stop_id)``,
``stop_idx``/``route_stop_count``, межостановочные интервалы и расстояния по
хаверсинусу. Индекс строится один раз и мемоизуется на самом DataFrame.

План нужен обоим сервисам: backend выбирает по нему целевую остановку, измеряет
отклонение live-ТС и строит граф каскада; ML service выводит из него статические
признаки и геометрию. Ни одна из сторон не импортирует код другой.

Причинность и честность
========================

Прогноз строится только по данным, доступным на момент ``T``: причинный срез
выполняется поиском ``np.searchsorted(times, T, side="right")`` для каждой точки
отдельно, поэтому увидеть будущее механически невозможно. Фактическое время
прибытия не читается: колонка ``time_fact_begin`` не используется ни в одном
модуле, что проверяется статическим анализом в ``ml/sanity_check.py``.
